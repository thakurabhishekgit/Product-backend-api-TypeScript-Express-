1. Create a New Migration ⭐⭐⭐⭐⭐ (Most Used)

Whenever you:

Add a model
Add a column
Remove a column
Rename a field
Add relations
Modify enums

npx.cmd prisma migrate dev --name init


Run:

npx.cmd prisma migrate dev --name init

Later

npx.cmd prisma migrate dev --name add-product-model

or

npx.cmd prisma migrate dev --name add-category-relation

or

npx.cmd prisma migrate dev --name add-user-status


| Command                                              | Usage                                          | How Often                     |
| ---------------------------------------------------- | ---------------------------------------------- | ----------------------------- |
| `npx.cmd prisma migrate dev --name <migration-name>` | Create migration + update DB + generate client | ⭐⭐⭐⭐⭐ Every schema change     |
| `npx.cmd prisma studio`                              | Open database UI                               | ⭐⭐⭐⭐⭐ Daily                   |
| `npx.cmd prisma generate`                            | Regenerate Prisma Client                       | ⭐⭐⭐ Occasionally              |
| `npx.cmd prisma format`                              | Format schema                                  | ⭐⭐⭐ Occasionally              |
| `npx.cmd prisma migrate reset`                       | Reset database                                 | ⭐⭐ During development         |
| `npx.cmd prisma db pull`                             | Generate schema from existing DB               | ⭐ Rare                        |
| `npx.cmd prisma db push`                             | Push schema without migration                  | ⭐ Rare (not for this project) |
| `npx.cmd prisma migrate status`                      | Check migration status                         | ⭐ Debugging                   |
| `npx.cmd prisma migrate deploy`                      | Apply migrations in production                 | ⭐ CI/CD                       |
